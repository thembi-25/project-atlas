# Analytics — PRD

## 1. Purpose

Provide Owner/Admin/Accountant-facing dashboards summarizing revenue, job volume, technician utilization, and outstanding invoices, and provide the Technician-scoped self-utilization view. See [Analytics](../03-domain/analytics.md).

## 2. Business problem

Owners of small field-service businesses run on gut feel because pulling real numbers means manually combining data from a scheduling tool, a spreadsheet, and accounting software — often only done at tax time, far too late to act on.

## 3. Goals

- A weekly-glance dashboard that answers "is the business healthy" without manual work.
- Numbers that are always reconcilable to the underlying Jobs/Invoices/Payments — no black-box aggregates.
- Role-appropriate scoping (a Technician sees their own utilization, not company revenue).

## 4. Non-goals

- Ad hoc/custom report building (pivot-table-style self-service BI) — see [Reporting PRD](./reporting-prd.md) for the boundary between fixed dashboards (this module) and exportable/custom reporting.

## 5. Personas

[Maria (Owner)](../00-overview/user-personas.md) primarily, [Priya (Accountant)](../00-overview/user-personas.md), [Curtis (Technician)](../00-overview/user-personas.md) for self-utilization.

## 6. User stories

See [User Stories](../01-product/user-stories.md); plus: As a Technician, I want to see my own utilization for the week, so I understand how my schedule compares to my teammates without seeing their individual numbers.

## 7. Functional requirements

Revenue-by-period dashboard; job-volume-by-type dashboard; technician-utilization dashboard (Team-scoped for Dispatcher, org-wide for Owner/Admin/Accountant, self-scoped for Technician); invoice-aging dashboard.

## 8. Business rules

Full detail in [Analytics](../03-domain/analytics.md) — notably: always tenant- and Role-scoped; materialized-view staleness is surfaced, never hidden; never becomes the system of record for a financial figure.

## 9. State machines

None — Analytics is purely derived, read-only.

## 10. Data requirements

Materialized views (`mv_revenue_by_period`, `mv_technician_utilization`, `mv_invoice_aging`, `mv_job_volume_by_type`) refreshed on a scheduled Worker job — see [Caching Strategy](../02-architecture/caching-strategy.md).

## 11. API requirements

`GET /api/v1/analytics/revenue?period=...`, `GET /api/v1/analytics/utilization?scope=self|team|organization`, `GET /api/v1/analytics/invoice-aging`.

## 12. Permission requirements

See [Roles](../03-domain/roles.md#role-to-module-access-summary) — Owner/Admin/Accountant: organization-wide. Dispatcher: own Team scope. Technician: self scope only.

## 13. UI requirements

Dashboard home page with the core widgets, each showing a "data as of HH:MM" staleness indicator; drill-down from any aggregate to the underlying Job/Invoice list.

## 14. Notifications

None directly (a weekly summary email digest is a candidate future extension, not launch scope).

## 15. Audit requirements

Analytics is read-only; no Audit Events are generated by viewing dashboards (view actions are not state changes — see [Audit Events](../03-domain/audit-events.md)).

## 16. Error cases

Requesting a Role-inappropriate scope (e.g., Technician requesting `scope=organization`) returns `403`, per [Authorization](../05-api/authorization.md).

## 17. Edge cases

A materialized view refresh fails/is delayed — the UI must show the last-known staleness timestamp accurately rather than silently displaying outdated data as if current; a failed refresh is itself alerted to operations (see [Monitoring](../10-devops/monitoring.md)).

## 18. Acceptance criteria

**Given** the revenue dashboard showing a total for a period, **when** an Accountant sums the underlying Invoices' `total` for that same period directly, **then** the two figures match exactly (see [Analytics](../03-domain/analytics.md), Business Rules).

## 19. Testing requirements

Materialized-view-accuracy tests (compare view output to a direct aggregate query); Role-scoping tests per dashboard; staleness-indicator accuracy tests.

## 20. Future extensions

Predictive/trend forecasting; Property Intelligence-informed dashboards (Phase 3); benchmark comparisons against anonymized industry data (Phase 7, [Industry Data Network](../13-roadmap/phase-7-industry-network.md)).
